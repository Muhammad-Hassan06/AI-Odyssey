# Provenance Audit Report: Pakistani-Context NER System

**Date:** 2026-10-21  
**Auditor:** Senior NLP Verification Engineer  
**Scope:** Dataset splits (`v2/train.jsonl`, `v2/dev.jsonl`, `v2/benchmark.jsonl`), rule engines, model checkpoints, and git provenance in `ner-pk`.

---

## 1. Executive Summary

This provenance audit was conducted prior to executing any code modifications or pipeline changes. Its objective is to rigorously inspect data sources, quantify label generation provenance, identify rule-sharing leakage between benchmark generation and inference, detail post-hoc benchmark fixes, resolve documentation discrepancies, and verify model checkpoint validity.

**Key Findings:**
1. **0 Benchmark Sentences Were Hand-Verified by a Human:** The internal benchmark (`v2/benchmark.jsonl`, 1,035 sentences) was generated 100% programmatically: 420 sentences (40.58%) from the synthetic generator (`src/synth.py`), 515 sentences (49.76%) pre-annotated from raw Wikipedia by `src/preannotate.py`, and 100 entity-free negative sentences (9.66%).
2. **Circular Evaluation (Leakage):** The predictor in `src/evaluate.py` directly executes the exact same gazetteers (`src/gazetteers/*.json`), regexes (`src/rules.py`), and pre-annotation heuristics (`src/preannotate.py`) used to assign benchmark labels. Running current pre-annotation code against benchmark text reproduces **94.0%** of benchmark entity spans verbatim.
3. **Four Post-Hoc Benchmark Error Fixes:** Git history reveals 4 specific rules added directly after viewing benchmark errors, contaminating the benchmark as a held-out evaluation set.
4. **Resolution of Discrepancies:** The 835 vs 1,035 sentence count discrepancy is traced to the Phase D initial benchmark (835 positive sentences) versus the expanded `v2/benchmark.jsonl` (932 positive + 103 negative = 1,035 sentences). The "1,00% Gold" phrase in `reports/final_report.md` was a typo for "100% Gold" (which itself is factually incorrect due to 40.58% synthetic data).
5. **No Trained Neural Model Exists:** The only checkpoint in `models/` is `models/smoke_test_model/`, a CPU smoke-test trained for 1 epoch of 4 steps (16 training samples) achieving **0.0 F1**. The reported 94.60% benchmark F1 was achieved entirely by rules and gazetteers.

## 3. Shared Code & Files Between Benchmark and Predictor

The evaluation harness in `src/evaluate.py` running in `--mode hybrid` or `--mode rules` imports and invokes the identical logic that created the benchmark:

```
[v2/benchmark.jsonl Generation]
          │
          ├──> src/preannotate.py ──┐
          ├──> src/rules.py       ──┼──> Exact Same Gazetteers (src/gazetteers/*.json)
          ├──> src/synth.py       ──┘
                                        ▲
[src/evaluate.py Inference]             │
          │                             │
          ├──> src/rules.py       ──────┤
          ├──> src/preannotate.py ──────┤
          └──> src/postprocess.py ──────┘
```

### Shared Files:
1. `src/preannotate.py`: `preannotate_text()`, compiled regexes for numbers, dates, times, money, percentages, and `KNOWN_EVENTS`.
2. `src/rules.py`: `extract_regex_entities()`, `extract_gazetteer_entities()`, `merge_spans()`.
3. `src/urdu_normalize.py`: `normalize_urdu()`, normalization applied during both annotation and inference.
4. `src/postprocess.py`: `postprocess_predictions()`, boundary trimming and label collision resolution.
5. All 10 Gazetteers in `src/gazetteers/`:
   - `cities.json`
   - `courts.json`
   - `educational_institutions.json`
   - `events.json`
   - `government_bodies.json`
   - `landmarks.json`
   - `laws.json`
   - `media_outlets.json`
   - `political_parties.json`
   - `sports_teams.json`

**Impact:** Evaluating `src/evaluate.py --mode rules` or `--mode hybrid` against `v2/benchmark.jsonl` does not test generalization to unseen Pakistani text; it primarily measures the self-consistency of the rule engine against itself.

## 4. Post-Hoc Fixes Made After Inspecting Benchmark Errors

Inspection of the repository commit history and `git diff` against base scraping commits reveals 4 explicit rule changes engineered specifically in response to benchmark error logs:

1. **`src/preannotate.py` (`ROMAN_URDU_COURTS`):**
   - *Change:* Removed `"High Court"` from `ROMAN_URDU_COURTS = ["Adalat-e-Uzma", "Adalat-e-Aalia", "Adalat-e-Insaaf", "Supreme Court"]`.
   - *Rationale:* In the benchmark, lowercase or uncapitalized "high court" appeared inside administrative text and was generating false-positive `COURT_LEGAL_BODY` hits.
2. **`src/preannotate.py` (`KNOWN_EVENTS`):**
   - *Change:* Added Urdu event phrases: `"پاکستان سپر لیگ"`, `"پی ایس ایل"`, `"یوم آزادی"`, `"یوم پاکستان"`, `"یوم دفاع"`, `"یوم تکبیر"`, `"وفاقی بجٹ"`.
   - *Rationale:* Benchmark Urdu sentences mentioning "پاکستان سپر لیگ" (PSL) were erroneously tagged as `COUNTRY` on "پاکستان" due to greedy regex matching before `EVENT` rules could trigger.
3. **`src/gazetteers/laws.json`:**
   - *Change:* Appended unspaced Urdu ordinal forms: `"26ویں آئینی ترمیم"` and `"18ویں آئینی ترمیم"`.
   - *Rationale:* Benchmark articles wrote ordinal numbers without a space before "ویں", causing missed `LAW_ACT` extractions.
4. **`src/gazetteers/government_bodies.json`:**
   - *Change:* Appended non-alif spelling variants: `"سٹیٹ بینک آف پاکستان"` and `"سٹیٹ بینک"`.
   - *Rationale:* Fixed benchmark misses where State Bank was spelled without the initial Alef ("سٹیٹ" vs "اسٹیٹ").

**Impact:** Tuning rules against benchmark errors invalidates the benchmark as an untouched hold-out test set. All subsequent tuning in Step 3 must be restricted strictly to `v2/dev.jsonl`.

## 5. Resolution of Documented Inconsistencies

### 5.1 Benchmark Size: 835 vs 1,035
- In Phase D (`PROGRESS.md`), the initial benchmark file `data/benchmark/benchmark.jsonl` contained **835 positive entity-bearing sentences** (plus 100 negatives added later = 935).
- When the dataset was upgraded to `v2/benchmark.jsonl`, additional synthetic and real evaluation pairs were incorporated, resulting in:
  - 515 Wikipedia sentences
  - 420 Synthetic sentences
  - 100 Negative sentences
  - **Total:** 1,035 sentences (932 entity-bearing, 103 negative).
- In earlier documentation (`reports/report.md` line 9), the text was not updated and continued to cite the old 835 count. The true size of `v2/benchmark.jsonl` is **1,035 sentences**.

### 5.2 Typo "1,00% Gold"
- In `reports/final_report.md` (and `reports/report.md`), the phrase `"1,00% Gold Benchmark"` was written.
- This is a typographical error for "100% Gold".
- Furthermore, the claim of "100% Gold" is factually invalid: 420 of the 1,035 sentences (40.58%) are synthetic template outputs, and 515 (49.76%) are code pre-annotated silver Wikipedia sentences without human verification.
